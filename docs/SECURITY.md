# 安全规范

## 1. 信任边界

- 本机操作系统管理员、DSH 宿主、NapCat、管理密码持有者属于信任边界。
- 原生源码插件是**可信宿主代码**，不是 JavaScript 沙箱；声明能力不等于隔离。
- 声明式扩展只执行固定规则，不加载任意脚本。
- QQ 普通用户、群友、转发内容、网页内容、模型输出都是不可信数据。

## 2. 管理站点

- 只监听 `127.0.0.1`，校验远端地址、Host、Origin。
- 密码使用 scrypt（N=16384,r=8,p=1）哈希，salt 随机 16 字节；文件 `admin.json`。
- 会话：HttpOnly + SameSite=Strict Cookie，12 小时绝对过期、30 分钟空闲过期。
- 写请求必须 CSRF；登录失败 15 分钟 5 次限速；请求体上限 256 KiB。
- CSP：`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'`。
- 不使用内联脚本、外部字体/CDN、`eval`、任意跳转。
- 密码修改后销毁所有旧会话；退出登录锁定该会话的秘密空间。
- 远程访问必须由用户自己加 HTTPS 反向代理；不要直接改监听地址为 `0.0.0.0`。

## 3. 私密秘密空间

### 3.1 两种空间

- **角色模式（新）**：角色通过现有受限 Agent 决定是否创建、选择一个密码气质、是否向主人分享；程序生成高熵密码并用设备密钥封装。用户界面不设置密码，也不显示密码。
- **旧版用户密码模式（兼容）**：v1 空间保留原密码解锁，避免已有数据失联；新空间不再默认走这条路径。

语言模型不接触密码明文，也不执行密码学运算。角色决策只返回 `create/choice/shareWithOwner/reason`；密码由 `generateCharacterPassphrase()` 生成，scrypt 派生，AES-256-GCM 加密内容。

### 3.2 加密方案

- 密钥派生：scrypt，N=16384、r=8、p=1，salt 随机 16 字节。
- 内容加密：AES-256-GCM，每条正文随机 12 字节 IV，16 字节认证 tag。
- AAD：`v1|secret|<id>`，防止密文串条。
- 初始化校验块：`v1|check`；解锁时解密校验块，错误密码不会返回正文。
- 角色密码封装：文字密码用 DSH 凭据库里的 32 字节设备密钥做 AES-256-GCM 封装，AAD `v1|character-key`。
- 文件 `data/dsh-onebot-bridge/private/secret-vault.json`：
  - `kdf`：算法与 salt；
  - `check`：验证块；
  - `keyWrap`：角色密码的设备密钥封装（仅角色模式）；
  - `entries[]`：id、iv、tag、密文、时间；
  - 不保存明文密码、明文设备密钥或明文标题/正文。
- 标题与正文一起加密；锁定状态只返回数量、模式和时间元数据。

### 3.3 决策、分享与锁定

- 首次启用且未初始化时，宿主在 QQ 在线后调用现有 `native.autonomy` 受限会话作一次决策；决策结果写入 `secret-decision.json`，不会每次重启重复创建。
- 角色选择不创建时保持未初始化，绝不生成默认密码。
- 角色选择分享时，管理员页面可以“请求查看”，解锁本次管理会话；密码本身仍不通过普通 API 返回。
- 角色选择保密时，页面只显示数量和“她选择保密”，不返回标题或正文。
- 解锁密钥只保存在宿主进程内存，绑定 `管理会话 + 页面级 nonce`；刷新、退出、15 分钟无操作都会重新锁定。
- 设备密钥存在 DSH 凭据库（`QQBOT_SECRET_DEVICE_KEY`），不写进 `private/` 目录。设备密钥丢失时无法恢复角色密码空间，只能清空。
- 旧版密码空间仍使用错误密码限速和内存会话锁定。

### 3.4 禁止

- 不得设置开发者可知的固定默认密码。
- 不得把随机生成说成无需角色决策的“自主”；必须保留真实决策记录。
- 不得用 Base64/异或/哈希代替加密。
- 不得把密码、设备密钥、明文正文写入日志、错误、遥测、URL、Cookie、localStorage。
- 不得在普通日记、记忆、设置页或 QQ 对话中自动带出秘密内容。
- 分享/复制必须由用户再次确认；密码原文不进入普通 API。
- 不得因为管理员拥有 3097 登录权限就自动显示保密空间内容。

## 4. 密钥与凭据

- OneBot Token 存在 DSH credentials / 状态中，界面只显示“已配置”，不回显。
- 嵌入模型密钥：界面不回显；保存时用 `preserveSecrets:['embeddingKey']` 保留未修改值；勾选清除才删除。
- 空间 Cookie 只通过 NapCat `get_cookies` 临时使用，不持久化、不返回前端、不入日志。
- QQ 空间缓存 `qzone/feed.json` 保存真实好友动态、评论和图片 URL，属于高敏感用户数据；不要发布、截图或纳入备份分享。图片经 `/api/qzone-image` 域名白名单代理，头像经 `/api/qzone-avatar` 代理。
- `.env`、`data/secrets.json`、`napcat/config` 不得进入发布包。
- 日志统一脱敏 Token、Cookie、`key=`、`token=` 等片段。

## 5. 权限

- 动作授权在服务端执行；前端隐藏按钮不算权限。
- 插件动作必须校验 owner/scope/active；普通用户不能通过前缀、引用或转发获得主人权限。
- 管理站点只允许本机会话；角色秘密空间还要求角色选择分享并请求查看。
- 市场安装、更新、卸载必须经过宿主动作和人工确认。
- 插件不得自行读取任意文件、访问任意 URL、调用 raw OneBot action。

## 6. 数据备份与恢复

- `state.json` 有 `.bak`；恢复前停止服务，校验 JSON。
- 记忆库 `memory.db` 可用 SQLite 备份；恢复后检查 `memory_reviews`。
- 秘密空间备份是密文文件，恢复后仍需密码；没有密码无法恢复正文。
- 不要备份到公开目录；不要把 `data/` 整体打包分发。
- 删除秘密空间是破坏性操作，必须先确认 `RESET`。

## 7. 数据导出

- 导出日记/记忆/活动前，页面要说明导出范围。
- 秘密正文导出必须再次验证密码并二次确认；默认不导出。
- 导出文件不包含管理密码、Token、Cookie、嵌入密钥。
- 导出后提示用户自行保管；不要自动上传。

## 8. 插件权限边界

| 能力 | 允许 | 不允许 |
|---|---|---|
| `actions` | 注册受控动作 | raw action、任意系统命令 |
| `events` | 订阅消息/通知/请求 | 读取未授权聊天 |
| `resources` | 通过媒体池读写 | 任意本机路径 |
| `storage` | 每插件 ≤64 KiB | 直接改 state.json |
| `context` | 回复前注入短文本 | 修改系统提示/权限 |
| `automatic-replies` | 预声明通知回复 | 无授权群发 |

## 9. 日志脱敏

- 记录插件 ID、动作、结果、耗时、错误摘要；不记录正文、密码、Token、Cookie。
- 错误信息截断 300 字；生产日志不要输出完整请求体。
- 秘密空间错误只返回“密码不正确/已锁定/数据损坏”，不返回解密细节。
- 发现泄漏时：停止服务、轮换 Token/密码、清理日志、检查备份，再恢复。

## 10. 安全测试

- `tests/admin.test.js`：密码、会话、CSRF、图片鉴权。
- `tests/admin-pages.test.js`：密文不含明文、锁定、错误密码、改密、清空。
- `tests/core.test.js`：权限、伪造上下文、资源边界。
- `tests/qzone.test.js`：空间端点、JSONP、写入限额。
- 新增敏感功能必须至少有一个“失败路径”测试。
