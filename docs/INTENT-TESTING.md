# QQ 框架 0.8.0：多主人、交流意图与表达习惯

日期：2026-10-30。已完成 192 项自动测试、6 项真实 DSH 与模拟 OneBot 联调。真实 QQ 写操作为 0，实际群聊请按下文测试。

## 本次变化

### 多主人

进入“设置 → QQ 框架 → 主人与授权”。保留主要主人 QQ，新增“其他主人 QQ”，可手动输入，也可点“选择好友”搜索并勾选。最多 20 位（包含主要主人）。保存后立即生效，旧任务授权撤销。

其他主人与主要主人拥有同样的机器人管理权限及已开启动作权限；群范围、暂停、明确拒绝和高危操作禁用规则仍生效。普通成员、群管理员、昵称和引用内容不能改变主人身份。主人列表只从本机设置页修改，不能在 QQ 里自封主人。新主人管理私聊始终接收；在群内使用仍需该聊天符合接收和回复范围。

升级保留原主人 10000001，没有替你添加任何其他真实账号。联调截图中的 98989898 是已撤销的本地模拟账号。

### 未 @ 的交流意图

进入“聊天对象 → 全局聊天默认设置 → 群聊”，新增“识别没有 @ 的呼唤和交流意图”，默认开启。

- @ 她或引用她的消息仍可直接唤醒。
- 未 @ 时，先以无工具模型结合昵称、配置称呼、人设中的自称和近期公开上下文，分析消息在和谁交流；名字可以出现在句中。
- 明确叫她、询问她或承接她的问题：正常回应，不受随机插话概率影响。
- 只是相关话题且有补充价值：仍需符合参与方式、随机回复概率、冷却和每分钟上限；“只在被叫时回复”不会顺带插话。
- 主人与群友相互交谈、转述或话题已结束：旁听。续聊窗口仅提供上下文线索，不能直接决定必须回复。
- 明确 @ 其他成员或引用其他成员的消息，不抢答。
- 判断格式错误、模型不可用或预算用完：保持旁听，不把内部错误发送到 QQ，也不借机开放工具。

语义判断会消耗模型用量；默认每群每分钟最多 12 次、每小时最多 180 次，可在“意图判断用量”调整。@ 入口不占这个判断预算。识别存在误差，可把“小鱼”等常用昵称加入“机器人称呼”提高明确性；原有人设正文没有被修改。

工具权限仍绑定本轮真实发言者。明确对她的请求才进入对应用户的受限执行；普通话题的参与仍为无工具聊天。模型判断“在叫她”不能把普通用户升级为主人，也不能开启电脑、服务器或任意脚本操作。

### 动作与语气

同页“表达习惯”中，动作描写和语气词分别可选：交给她自然表达、关闭／少用、按概率允许。默认保留原表达风格；概率模式默认 30%。概率按一轮抽取，允许不等于强制出现。

允许时保留完整“（甩尾）”等表达。关闭时首先要求模型不用动作描写，并整体过滤明确动作片段；不会只删除括号后留下“甩尾”。正常备注、单位和数学括号保留。语气词关闭减少独立感叹和填充词，保留有意义词汇；自然语言变体通过提示要求与有限过滤共同约束，并非任意语句的词性识别器。

这次只改变聊天行为与可配置表达，不修改人设原文，也不新增系统操作权限。

## 你的测试步骤

1. 刷新设置，在“主人与授权”用“选择好友”添加你信任的账号并保存。请其私聊“机器人状态”，应可管理；未添加的普通账号不应因此获得管理权。移除该账号并保存后重新试，应不再具备主人权限。
2. 确认允许测试群及对应成员聊天，开启无 @ 意图识别。先把随机回复概率设为 0：说“小鱼在不在？”或“我问的是你呀，小鱼”，应能结合昵称和人设识别，不要求每条 @。
3. 你与另一群成员连续聊天，例如对方 @ 你问“这是怎么改的”，你答“我用 codex 改的”，她应旁听；不能仅因你是主人或刚与她聊过就插话。
4. 让普通成员无 @ 叫她、问一个问题，应能按聊天范围回应；再让该成员要求操作电脑或服务器，应不能执行。
5. 把随机回复概率调到合适值，聊与她相关但没有叫她的话题：她可偶尔补充，但需受冷却和条数限制；把概率恢复 0 后相关闲聊不应继续随机插话。
6. 动作描写选“交给她自然表达”，观察“（甩尾）”等完整动作不会被去掉括号；选“不发送动作描写”后，不应只剩下裸动作词。正常“这个值（单位：米）”应完整。
7. 动作／语气概率设 0，应与关闭一致；设 100 仅允许出现，不强制每句话添加。中间概率需多轮观察，单条不能判断概率准确性。
8. 保存后刷新，检查主人列表、表达方式和概率持久化。原有人设、绑定、29 项已开启动作及群范围均应保留。
