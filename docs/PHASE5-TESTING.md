## 本次行为

- 引用消息会补齐原发送者与原文，并处理引用内的图片、语音、文件、视频；最多展开两层引用、四个附件。优先查同一聊天缓存，再从 OneBot 获取并验证范围。无法确认所属聊天时不投递原文，不拿最近附件冒充。
- 群内成员共用公开聊天背景；每次模型执行采用新的受限会话，只带入公开消息和实际已发送的回复。工具的内部结果、上一轮授权与私聊记录不加入群时间线。同一个群只保留一个当前执行入口，旧执行记录归档。
- 背景取最近 6 小时、最多 40 条、合计约 14000 字符；单条背景上限 1500 字符，明确引用的单条正文上限 6000 字符。这是近期上下文，尚未实现长期人物关系记忆。
- 人设以当前实际启用、绑定的提示词进入模型；每次执行前检查最终提示词及刷新结果。人设或目录隔离检查不通过则停止该轮。
- 默认每轮最多 240 字、2 条，工具主动发送和最终回复共用额度。聊天设置可调整为总字数 80–4000、条数 1–6。分条模式继续可选；段落过多时合并。超出预算的正文会缩短并以省略号结束，完整模型输出仍可在本机 DSH 执行记录查看。
- 自动回复、插件文字发送、入群欢迎及已配置事件回复都会处理本机路径、已知网关令牌与明显凭据格式。不会向 QQ 提供真实工作目录。
- 没有文件名的附件会尝试获取网关 file_name；无后缀且体积不超过 128 KB 的有效 UTF-8 文本可直接提取。保留文件大小、格式、解压和解析时限。

## 开始前

1. 刷新 DSH 页面，确认 NapCat 已登录且“运行状态”显示 QQ 在线。
2. 在“聊天”中确认允许群聊、所选群和群内用户范围；测试时建议暂时选择“只在被叫时回复”，避免随机插话干扰。
3. 在“人设”确认人设包已启用、默认/当前群绑定正确。可以先用短人设测试，例如：“你叫青禾，轻松简短。别人问好时说‘青禾来啦’，再自然接一句。”
4. 在“聊天 → 回复方式”查看每轮总字数与条数。记录原值，测试后按需要恢复。

## 0.5.1 补充：戳一戳回应

已加入群聊和私聊的戳一戳互动，默认开启。入口：设置 → QQ 框架 → 聊天 → 戳一戳。

- 只回应“有人戳机器人”，不回应群成员互戳或机器人自己发出的戳一戳。
- 使用当前聊天绑定的人设和近期上下文，最多一句短回复；发送端最多 80 字、1 条。
- 同一聊天、同一人默认冷却 30 秒，可设置为 5–600 秒。每个聊天另有 10 秒间隔；上一条尚在处理时不会堆积戳一戳任务。
- 戳一戳仅作互动，主人也不会因戳一戳获得本轮工具调用；不会自动回戳。
- 沿用聊天用户/群范围、暂停状态和 AI 聊天包开关，并需要“监听成员变动与其他通知”开启。无须额外 @机器人。

一起验收：

| 项目 | 操作 | 预期 |
| --- | --- | --- |
| 群内回应 | 在允许聊天的群里戳机器人一次 | 她按当前人设回应一句，没有错误的消息引用 |
| 连续戳 | 紧接着再戳几次 | 冷却内不刷屏；正在处理时不堆积任务 |
| 冷却恢复 | 等待 30 秒再戳 | 可以再次回应；具体等待时间以设置值为准 |
| 成员互戳 | 戳群里另一位成员 | 机器人不为这次事件接话 |
| 私聊回应 | 在允许聊天的私聊中戳机器人 | 只在该私聊中回应，不发到群里 |
| 停用 | 关闭“回应戳一戳”并保存，再戳机器人 | 不回应；重新开启保存后恢复 |
| 人设和工具 | 切换当前人设后戳机器人 | 按新人设回应，不执行群管理、文件或其他工具 |

本次自动验证：101 项回归测试；真实 DSH 模型通过模拟 OneBot 通知验证群/私聊回应、零工具、单条短回复、冷却和设置界面。没有向真实 QQ 发送测试消息。记录：data/poke-tests.log、data/poke-integration.json。

## 0.5.2 补充：不 @ 的同群接话

原先“允许短暂续聊”只认同一发起者（30 秒、两轮），换人追问会回到普通群消息的随机概率。现在增加同群话题窗口：

- 她实际发出回复后，90 秒内其他成员直接问“你……”、追问“为什么/然后呢”，或围绕刚才的话题继续提问，可以不 @ 接话。
- 新增接话每个话题最多 3 次、每群每分钟最多 3 次，间隔至少 3 秒，上一轮未完成时不叠加任务；接话本身不会无限延长窗口。
- 明确 @其他人、回复其他成员的消息，以及未明确唤醒的纯媒体，不抢着接话。“每条消息都回复”模式仍保留原有媒体处理。
- 同一发起者原有的 30 秒两轮续聊继续保留。关闭“允许短暂续聊”会同时关闭这两种续聊。
- 非明确唤醒的同群接话只允许当前发言者已经获授权的安全查询；群管理、修改与发送工具不能借接话触发。主人在群里执行管理动作时请明确 @、引用机器人或使用配置的称呼。
- 全新、无关的话题仍按现有随机概率处理；本次没有把 10% 改成“每条必回”。

一起测试：甲 @机器人开启一段聊天；她回复后，乙不 @发送“你有鲸鱼娘专武吗？”，或丙追问刚才的话题。应出现自然回复，任务的触发原因是 context。然后让乙 @另一名成员或引用另一名成员交谈，机器人不应抢答。超过 90 秒后，全新话题按普通参与策略处理。

107 项回归测试通过；真实 DSH + 模拟 OneBot 已将随机概率设为 0，验证不同成员无 @接话和共享背景，之后恢复原设置。结果：data/followup-tests.log、data/followup-integration.json。


## 0.5.4 补充：自然排版与减少复读

已取消红包适配：未启用的 NapCat 适配文件已归档，相关接收逻辑和设置项已撤下。NapCat 不需要重启，QQ 登录保持不变。

本次调整：
- 默认不附引用框。入口“聊天 → 回复方式 → 引用原消息”，可选“不附引用框 / 只在用户引用提问时 / 每次都引用”。你发来的引用仍会补齐原文给模型。
- 兼容旧人设示例中的中文“ / ”分隔，自动聊天中改成真实换行。网址、算式、代码不做这种转换；明确使用发送工具指定的原文也保留。
- 人设保存的原始提示词和版本不变。运行时把旧 send_message 数组等排版约定转为当前框架能理解的表达规则，示例只用来参考语气。
- 群背景继续保留成员发言，但只带入最近三个不重复的机器人表达，避免自己的旧台词不断强化旧话题。
- 近期饮食梗过多而本轮没问饮食时，提示模型换话题；主动问食物仍可保留白饭等角色喜好。
- 纯聊天草稿明显重复时，最多做一次无工具改写；仍然重复则不刷出该条，任务显示“略过重复回复”。已经调用工具的结果不走该改写流程，避免重做操作。
- 保留跨成员无 @ 接话、戳一戳、媒体、权限与整轮字数/条数控制。

一起验收：
1. 群里 @她说一句话：默认不再出现大块引用框。
2. 引用一条消息再问：她能读懂原文，自己的回复仍不强制加引用框。
3. 连续换几个话题，例如“你牛大了”“聊聊最近的天气感受”“你加了什么功能”：不应每轮都绕回吃饭，也不应把玩笑说成真实代码。
4. 直接问“喜欢吃什么”：仍可按原来的人设回答。
5. 观察排版：聊天停顿用正常换行，不再照抄“ / ”分隔。
6. 主动要求“把原话重复一遍”：应允许正常复述；算式“10 / 2”和网址仍保持原样。
7. 想恢复引用时，切换“每次都引用”并保存；测完可改回“不附引用框”。

自动验收：119 项回归测试通过；真实 DSH + 模拟 OneBot 验证了改写隔离、原文发送、切换话题、饮食喜好保留、入站引用理解、可选引用设置及界面。模拟测试没有向真实 QQ 发送消息。
记录：data/natural-tests.log、data/natural-integration.json。

自然表达仍由模型生成；这些改动用来减少固定台词和重复强化，不保证每一句都符合你的审美。若仍有生硬回复，保留前后几条对话继续调整。
