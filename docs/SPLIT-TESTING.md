# QQ 框架 0.6.1：分条发送验收

日期：2026-10-30。

问题原因：原来的“按段落分条”只识别空行。模型输出单换行时，会保留在同一个气泡。之前把旧人设斜杠转换成了换行，没有补齐这一步。

现已增加“自然分条”，并按你的选择设为当前使用方式。截图中的“哦，行吧”和“那我继续趴着了”应是两个独立气泡，沿用当前 1100 毫秒发送间隔和每轮最多 2 条。

## 测试

1. 刷新 DSH，进入设置 → QQ 框架 → 聊天对象 → 全局聊天默认设置 → 回复方式。分条发送应为“自然分条（短句换行分开发）”。
2. 在 QQ 中让她回复两句完整短句，中间换行。应看到两个独立消息气泡，而不是同气泡两行。若模型本次只说了一句，不会强行拆成两条。
3. 再测试三句短话：当前上限两条，因此第一句单独发送，后两句在第二条合并；不会突破整轮条数。想允许三条，可调整每轮最多条数。
4. 测试一个列表或代码块，不应每行变成独立消息。明确工具发送和戳一戳继续遵守自己的单条语义。

## 验证记录

145 项自动回归通过，包含截图原文的两次 OneBot 调用、发送间隔、尾部合并、Unicode、代码列表、工具共用预算与戳一戳单条。

真实 DSH 模型 + 本地模拟 OneBot 已逐字复现截图原文，并确认发送为两个独立消息，间隔符合当前设置。没有向真实 QQ 发送测试消息。测试后恢复真实 NapCat 连接，保留人设、29 项动作和原有授权。
