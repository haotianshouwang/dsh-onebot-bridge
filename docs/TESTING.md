## 1. 测试前准备

1. 打开 DSH（http://127.0.0.1:3080），刷新页面，进入“设置 → QQ 框架”，应有“连接、聊天、媒体、监听、主人与权限、人设、插件管理、运行状态”八个页签。
2. 打开 NapCat（http://127.0.0.1:6099/webui）。如果 QQ 离线，重新扫码；不需要更换 Token。也可双击项目 open.cmd 打开本机入口。
3. 在“连接”测试 OneBot，在“媒体”点击“检查当前模型”。应显示实际使用的模型与是否支持图片。插件仍继承你原来的 DSH 默认模型，没有擅自切换。
4. 当前 NapCat 已保存 enableLocalFile2Url=true，目的是让 get_image/get_file 返回附件字节，避免把网关电脑路径当成文件内容。QQ 登录时加载；如果界面提示未返回附件字节，确认该项已生效，必要时在 NapCat 的 OneBot 配置中重新保存。
5. 准备一个测试群、主人账号和另一个普通 QQ。测试期间不要连发过快：原有每用户每分钟限制仍有效。
6. 不要用真实密码、身份证或私人文档做测试。可以自己制作只有“测试口令 4681”的文本和测试图片。

## 3. 群聊不再每条回复

“聊天 → 群聊参与方式”有三档：

- 只在被叫时回复：@机器人、以配置称呼开头，或引用本次运行中机器人发出的已知消息才触发。
- 适度参与：上述情况直接触发；其他普通群消息按概率参与，受冷却和每分钟上限限制。
- 每条消息都回复：保留显式选项，不作为本次推荐配置。

本次默认采用适度参与：普通消息 10%，随机回复冷却 30 秒，每群每分钟最多两次随机触发；机器人称呼可在同页编辑。概率是抽样，不表示每十句必须固定回复一句。纯图片/语音/视频不会随机插话，@其他人的消息也不随机接话。

随机参与只聊天，不执行任何工具，即使消息发送者恰好是主人。需要查询或操作时，明确 @或叫机器人即可。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| R1 | 在测试群 @机器人问一个简单问题 | 正常回复，不受 10% 概率影响 |
| R2 | 将概率设为 0，暂时关闭“允许短暂续聊”，不 @、不叫名，发三条普通消息 | 不触发 AI；运行状态能看到未命中概率等原因 |
| R3 | 保持概率 0，使用已配置称呼开头提问，例如“测试项目，今天聊什么” | 仍正常唤醒，不需要斜杠命令 |
| R4 | 引用机器人本次运行中刚发出的回复继续提问 | 正常唤醒；重启前的旧引用未保存在内存账本时，请改用 @ |
| R5 | 暂设概率 100、冷却 30 秒、上限 2，关闭续聊，短时间发三条未唤醒普通消息 | 不会三条都回复；已有随机任务、冷却或额度会阻止后续触发 |
| R6 | 打开短暂续聊，@机器人交谈，再由同一个 QQ 继续两句 | 同一个发起者最多在 30 秒内续两轮；不会无限延长，其他 QQ 不继承该窗口 |
| R7 | @另一位群友而不 @机器人 | 机器人不因随机参与插话 |
| R8 | 私聊机器人 | 不使用群聊随机概率；原有用户范围和速率限制仍有效 |

完成后恢复推荐值 10%、30 秒、2 次。若希望更安静，选“只在被叫时回复”；设置不需要重连 QQ。

实现参考了 [AstrBot 的唤醒检查](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/pipeline/waking_check/stage.py)对 @、引用和前缀的区分，以及 [MaiBot 的触发调度](https://github.com/Mai-with-u/MaiBot/blob/main/src/maisaka/turn_trigger/scheduler.py)将消息门控、频率和退避分开的思路。本框架实现的是上述轻量策略，没有复制其运行器，也没有定时主动暖场。

## 4. 图片

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| M1 | 私聊发送一张带四位测试数字的清晰图片，问“图片里的数字是什么” | DSH 会话中有真实图片附件；模型答出数字，不再仅看到 [图片] |
| M2 | 群里 @机器人并附图片，或先发图再 @问“看一下刚才的图片” | 能处理同一发送者两分钟内的最近附件 |
| M3 | 两个人先后发图，再由其中一人问“刚才那张图” | 仅关联该发起者自己的附件，不混用另一个人的图片 |
| M4 | 媒体页关闭“接收图片”后重新发图 | 明确说明处理关闭，不伪装看到了内容；重新打开后恢复 |

视觉模型得到真实 image 内容块，DSH 保存为持久图片附件。当前模型若不声明图片能力，会尝试 NapCat OCR；OCR 只能识别文字，不能据此声称理解场景、人物、颜色。OCR 不可用时会明确提示。图片格式支持 PNG、JPEG、GIF、WebP；动画不保证逐帧理解。

## 5. 语音

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| A1 | 私聊发一段短语音，说“测试口令是三五七九”，再问识别结果 | NapCat 按原消息 ID 转写；转写文字送入 DSH，原语音尽可能以 WAV 文件附加 |
| A2 | 群里先发语音，再由同一 QQ @问“刚才的语音说了什么” | 使用该 QQ 最近语音的原消息 ID，不误用当前文本消息 ID |
| A3 | 发噪声或 QQ 转写服务无法识别的语音 | 明确说明没有成功转写，不编造内容 |
| A4 | 关闭“接收语音”再试 | 不转写、不假装听懂 |

当前使用 NapCat fetch_ptt_text，实际识别质量与可用性取决于 QQ；不是模型直接“听”WAV。若转写成功但原文件取回失败，仍可依据转写回答，媒体页会区分结果。

## 6. 文件

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| F1 | 私聊发送 TXT/Markdown/CSV/JSON，内容写独特测试口令 | 原文件作为 DSH 文件附件保存；提取正文进入模型，能回答口令 |
| F2 | 发 DOCX，正文写测试口令 | 提取正文；不执行宏、脚本或外部链接 |
| F3 | 发带真实文字层的 PDF，问前几页内容 | 最多提取前 10 页，正文最多 20000 字 |
| F4 | 发扫描 PDF、加密 PDF、压缩包或未知二进制格式 | 可以保存原文件，但没有正文或解析失败时明确说明，不能声称读懂 |
| F5 | 群里上传文件，再由同一 QQ @问“读一下刚才的文件” | group_upload 文件通知被识别为附件，后续请求能关联，而不是丢失文件 |
| F6 | 另一人试图让机器人读取别人刚发的文件，或输入本机路径要求读取 | 不通过附件缓存读取他人的文件，不接受任意本机路径；若要分析共享文件请重新附上 |

部分群文件、离线文件由 OneBot 通知而非普通消息投递，已做适配。DSH 的“有文件附件”本身不代表模型获得了文件正文，本版会单独提取支持格式；扫描 PDF 暂不做整份 OCR，可把所需页另发图片。代码文件只作为文本分析，不执行。

## 7. 视频

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| V1 | 发一个两到十秒、画面明显的短 MP4，问主要颜色或场景 | 原视频附加到 DSH，提取前 15 秒内最多 3 帧画面交给视觉模型 |
| V2 | 发超过 15 秒但小于大小上限的视频，问后半段内容 | 不能据此断言没观察到的后半段；处理说明会标出取样范围 |
| V3 | 询问视频中的语音对白 | 当前不转写视频音轨，应明确说明，不能冒充听懂 |
| V4 | 缺少 ffmpeg、视频损坏或格式不兼容 | 尽可能保留原视频附件，同时说明抽帧失败，不装作看过画面 |

当前主要支持 MP4/MOV 容器；抽帧是固定参数的框架内部转换，没有向 QQ 模型开放进程或命令工具。

## 8. 限制与安全

- 单附件最多 8 MB，每条最多四个，合计最多 16 MB。超过上限应给出处理说明。
- 下载只接受公开 HTTPS，检查 DNS、跳转和体积；网关返回的本机文件路径不会由插件直接读取。
- PDF 在有内存和时间限制的独立工作线程中提取；视频转换有时间、输出大小和协议限制。
- 附件正文、OCR、转写与转发内容都是用户数据，不能授予主人身份或扩大权限。
- 请在已唤醒的会话测试“执行服务器命令”“读取电脑密码文件”等请求，应被拒绝；不能因为传了一份代码文件就运行它。
- 修改媒体或权限设置会撤销旧任务；普通用户仅能使用主人明确共享的查询工具。
